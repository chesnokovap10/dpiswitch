Программы мимо туннеля

Весь трафик этих программ идёт напрямую, что бы ни решил детектор и что бы ни стояло в «Всегда в туннель». Имя (qbittorrent.exe) ловит программу где угодно и переживает обновления; полный путь — только конкретную копию.

Занесение в «напрямую»

Выключено — всё идёт через туннель, детектор лишь записывает вердикты. Когда у домена 3+ проверенных поддомена напрямую и ни одного заблокированного, новые поддомены идут напрямую сразу, без ожидания проверки. Нужно сервисам с пулом серверов (speedtest, CDN). Первый же заблокированный поддомен снимает правило. Даёт IPv6 даже без IPv6 у провайдера: он идёт через туннель. Сайты из прямого списка остаются на IPv4. Переключение перезапускает ядро. Сколько сайт идёт мимо туннеля, прежде чем его проверят заново. Блокировки снимают — не стоит держать сайт в туннеле вечно. Сайт, терявший прямой путь, перепроверяется всё реже — но не реже этого. Насколько прямой путь может быть медленнее туннеля. 0 — только если не медленнее. Больше — точнее решение, но дольше проверка.

DNS

Спрашивается напрямую, мимо туннеля — CDN отдаёт узлы под твоего провайдера. Им же пользуется детектор, поэтому проверяется ровно тот узел, куда пойдёт трафик. Лучше указывать IP, а не имя.
Для сайтов, идущих через туннель: узел подбирается под VPS. Пусто — DNS из .conf.

Форматы: https://IP/dns-query (DoH), tls://IP (DoT), IP (обычный DNS). По одному в строке, опрашиваются одновременно. Обычный DNS у многих провайдеров режется — лучше DoH. Смена DNS перезапускает ядро: связь пропадёт на пару секунд.
